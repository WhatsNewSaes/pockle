## Responsiveness — v1.2.0

The user reported lag and that the device handled one action at a time before freezing. Causes found in the vendor Arduino example and the v1.1.1 loop: SPI bit-banged through `digitalWrite` (about 1.3 million GPIO calls per frame), a 1 ms sleep per row in every frame writer, a fixed 100 ms sleep before each busy poll, a synchronous ~5 s full refresh on every twelfth key press, and a main loop that blocked on the panel so key presses queued behind it.

- Panel transport is now hardware SPI at 20 MHz, mode 0, matching the vendor ESP-IDF port; frames stream as one transfer with CS held. Register sequences are unchanged.
- Display updates are non-blocking: the loop renders, sends the frame, starts the refresh, and returns. Input continues to update state while the panel is busy and is drawn as one frame the moment it is free. Identical frames are not sent. A frame is no longer redrawn just to show "UPDATING SCORES…" when scores are already on screen.
- Ghost-cleaning full refreshes run only when idle (no key for 2.5 s): the panel's fast base refresh after eight partial updates, and a slow full refresh every 30 minutes. Score cache writes moved to the network task.
- Measured on the device over USB: frame transfer 63 ms (previously ~800 ms of bit-banging); partial refresh completes 512–521 ms after the send, which is the panel's own waveform; fast cleanup refresh 1,710 ms. A burst of three presses drew the first immediately and the remaining two as a single frame right after — no freeze. Nine rapid presses each drew in turn, then the idle cleanup ran and a following press drew normally.
- No spurious button events were observed at rest over 12 s or in the 10 s after a refresh. Extra rocker-down events seen during rapid USB testing coincided with the user handling the device and are treated as real presses.
- `?` over USB now also reports `PANEL partials= pending= busy= idleMs= sinceFull= keysQueued=` for the display pipeline.
- Firmware compiled at 1,510,267 bytes (36% of the slot); native tests pass; both uploads verified by flash hash.
- The user confirmed the physical panel matched the USB framebuffer capture after partial updates (date picker page), verifying the hardware SPI transport and the non-blocking pipeline end to end.

## Spoken replies — v1.3.0

## Idle sleep with refresh wakes — v1.3.0

The user wanted battery savings without a deceptively static page. After ten idle minutes the board renders its current page with an "asleep" banner (press any button, scores-as-of time, battery percentage from the AXP2101 fuel gauge register 0xA4), powers the panel down, and deep-sleeps with three wake sources: EXT1 on GPIO 0/4/5/6 (any low; RTC pull-ups kept powered), a 15-minute timer for a refresh cycle, or the 6:30 am timer at night. On a timer wake the board restores the tab from RTC memory, fetches the feeds the page needs (four on ALL, one on a league tab) with the fetch cadence forced to back-to-back, redraws, and sleeps again; any key press during that window cancels it and keeps the board awake. Device: `I` forced an idle sleep — `SLEEP idle: wake in 900s (night=0) battery=100%` — and USB enumeration disappeared. The refresh wake was then observed: USB reappeared about 885 s after the sleep, the board fetched both feeds the ALL tab needed (`FETCH league=0 ... games=81`, `FETCH league=1 ... games=48`), and it slept again within seconds. The user then asked for the banner to be centered with the second line larger, so both lines are centered and drawn at text size 2 (`ASLEEP - <time> - BATTERY nn%`, at most 30 characters so it fits 480 px). The user then moved the banner to the top of the panel (y 0–52) so it reads first.

## Speech playback smoothness — v1.3.0

The user heard pauses and clipped words. Cause: speech was written to I2S straight from the network-reading loop, so any slow SSE chunk or the time spent parsing the next line let the DMA buffer run dry. Playback now goes through a 1.5 MB PSRAM ring buffer: the network side decodes into it, a dedicated `speaker` task waits for 0.8 s of audio (or the end of the stream) before enabling the amplifier and then feeds the codec continuously; `playEnd` waits for the task to drain. A USB `S<text>` command (`device_console.py say [--text ...]`) speaks arbitrary text for tuning. Device: a 7.1 s test sentence played end to end (470 KB SSE → 341 KB PCM). The user's ear is the remaining check.

## Sleep current — v1.4.0

Overnight (11 pm to 6:30 am, no wakes) the battery went 100% to 94%: about 0.8%/h of pure sleep current, far above what the ESP32-S3's deep sleep costs. Selecting a team on a matchup, or a favorite, opens the page; its top row toggles the favorite; BOOT returns to the matchup (or Favorites) it came from via a remembered origin. Team caches are `/t<league>_<id>.json`, pruned to 24.

- Native tests: schedule decode keeps every date, reads nested scores, season type and week; trimming leaves results plus exactly one upcoming game, newest first; the cache round-trips the team id.
- Device: Home → NFL → first matchup → select a team → schedule fetched (HTTP 200, 17 events, 260,935 bytes, heap 231 KB) → page drew with 3 results and the next game → BOOT drew the matchup again. Firmware 1,532,255 bytes; flash hash verified.
